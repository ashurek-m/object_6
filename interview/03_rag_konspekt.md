# RAG — конспект для собеседования

## Одной фразой

**RAG (Retrieval-Augmented Generation)** — генерация с дополнением из поиска: перед ответом LLM автоматически находит релевантные куски из базы документов и подкладывает их в промпт. Модель отвечает по документам, а не «из головы».

## Какую проблему решает

- У LLM нет внутренних документов компании (регламенты, ГОСТы, ТУ).
- Контекстное окно ограничено — тысячи страниц не «залить» в промпт.
- Данные часто нельзя выгружать наружу (информационная безопасность).
- Без документов модель галлюцинирует.

## Как работает

```
ИНДЕКСАЦИЯ (один раз, при обновлении документов):
  Документы → нарезка на куски ~500–1000 символов (чанкинг)
  → каждый кусок → эмбеддинг (вектор смысла)
  → сохранение в векторную БД

ЗАПРОС (в момент вопроса):
  Вопрос → эмбеддинг → векторный поиск топ-K ближайших кусков
  → промпт: «Ответь на вопрос ТОЛЬКО по этим документам: …»
  → LLM отвечает со ссылками на источники
```

Семантический поиск находит «как оформить отгрузку» по куску про «порядок отпуска продукции со склада» — общих слов нет, совпадение по смыслу. Этого не умеет `LIKE` и полнотекстовый поиск.

## Термины

| Термин | Что это |
|---|---|
| Эмбеддинг | Вектор, кодирующий смысл текста; близкие по смыслу тексты → близкие векторы |
| Векторная БД | Хранилище эмбеддингов с быстрым поиском ближайших: Qdrant, pgvector, Chroma, FAISS |
| Чанкинг | Нарезка документов на куски; от размера зависят качество и стоимость |
| Top-K retrieval | «Взять K самых релевантных кусков» (обычно 3–10) — как `SELECT TOP K`, но по смыслу |
| Гибридный поиск | Семантика + полнотекстовый поиск (для артикулов, номеров ГОСТов) |
| Re-ranking | Пересортировка найденного второй моделью по точной релевантности |

## 30-секундный ответ на собеседовании

> «Это когда перед ответом LLM мы автоматически находим релевантные куски из базы знаний компании и подкладываем их в промпт. Модель отвечает по документам, а не из памяти — нет галлюцинаций, можно давать ссылки на источники, и не нужно дообучать модель. База обновляется без переобучения: добавил документ — ассистент уже его знает».

## Вероятные вопросы и ответы

**«Почему не дообучить модель на документах?»**
RAG дешевле и обновляется мгновенно; файнтюн меняет стиль поведения модели, а не знание фактов. Для «знания» документов стандарт индустрии — RAG.

**«Какие эмбеддинг-модели?»**
В личных сценариях — API-эмбеддинги (OpenAI-совместимые). Промышленный выбор зависит от ИБ-требований и языка; сравнивают по бенчмаркам (MTEB) на своих данных.

**«Главная проблема RAG?»**
Качество нарезки и поиска: если нужный кусок не попал в топ-K, ответ будет плохим. Поэтому измеряют качество поиска, настраивают чанкинг и применяют гибридный поиск.

**«Где применяли бы у нас?»**
Ассистент по техрегламентам и ТУ: сотрудник спрашивает про требования — получает ответ из документов компании с указанием файла. Плюс onboarding новых сотрудников.
