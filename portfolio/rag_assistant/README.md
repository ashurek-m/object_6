# RAG-ассистент по производственной документации

Демо-проект: ассистент отвечает на вопросы по техническим регламентам и стандартам предприятия, **указывая источник каждого ответа** (файл + раздел + фрагмент). Закрывает ключевое требование вакансии AI Engineer — «RAG-ассистенты для работы с документами».

**Главная особенность схемы:** один и тот же код работает и с локальными моделями (Ollama — документы не покидают компьютер), и с любым облачным OpenAI-совместимым API. Переключение — 2 строки в `.env`. Для промышленного заказчика с ИБ-ограничениями локальная схема — готовый ответ на возражение «данные нельзя в облако».

## Как это работает

```
ИНДЕКСАЦИЯ (python ingest.py, при обновлении документов):
  data/docs (.md/.txt/.docx)
    -> нарезка на куски ~900 символов с перекрытием 150 (чанкинг)
    -> эмбеддинги каждого куска (bge-m3 через API)
    -> векторная БД Chroma (локально, без сервера)

ЗАПРОС (python query.py / streamlit):
  вопрос -> эмбеддинг -> векторный поиск топ-5 кусков по смыслу
    -> промпт: «отвечай ТОЛЬКО по фрагментам, ссылайся как [1], [2]»
    -> LLM отвечает + список источников с мерой близости
```

Семантический поиск находит ответ и там, где дословного совпадения нет: «как отгрузить продукцию» найдёт раздел «Порядок оформления отгрузки». Этого не умеет `LIKE` и полнотекстовый поиск.

## Быстрый старт (Windows)

1. **Python 3.12** + venv с зависимостями:
   ```bash
   python -m venv .venv
   .venv\Scripts\pip install -r requirements.txt
   ```
2. **Настройка**: скопировать `.env.example` в `.env`. По умолчанию — локальный Ollama; для облачного API раскомментировать нужный блок.
3. **Модели Ollama** (если используется локальная схема):
   ```bash
   ollama pull bge-m3      # эмбеддинги, ~1.2 ГБ, мультиязычная
   ollama pull qwen3:4b    # ответы, ~2.6 ГБ
   ```
4. **Документы**: положить файлы `.md`, `.txt` или `.docx` в `data/docs/` (в репозитории есть 2 демонстрационных документа — скопируйте их из `data/examples/`).
5. **Индексация и запуск**:
   ```bash
   run_ingest.bat          # или: python ingest.py
   run_cli.bat "До какого времени принимают заявки на срочную отгрузку?"
   run_web.bat             # веб-интерфейс на http://localhost:8501
   ```

## Что здесь есть

| Файл | Назначение |
|---|---|
| `config.py` | настройки из `.env`: адрес API, модели, параметры чанкинга |
| `llm_client.py` | HTTP-клиент `/v1/chat/completions` и `/v1/embeddings` (requests, без SDK — видно, как устроен API) |
| `ingest.py` | загрузка документов, чанкинг, эмбеддинги, заливка в Chroma |
| `query.py` | векторный поиск + промпт + ответ со ссылками `[1]`… + консольный интерфейс |
| `app.py` | веб-интерфейс (Streamlit): вопрос → ответ → раскрывающиеся источники |
| `eval.py` | мини-оценка качества **поиска**: попал ли нужный документ в топ-K |
| `data/examples/` | 2 демонстрационных документа (синтетические регламенты) |
| `data/docs/` | рабочая папка документов — **в git не попадает** (реальные документы предприятия не публикуются) |

## Решения, о которых стоит спросить на собеседовании

- **Почему RAG, а не дообучение модели** — документы обновляются без переобучения: добавил файл, переиндексировал — ассистент уже знает; файнтюн меняет стиль, а не факты.
- **Чанкинг 900 символов с перекрытием 150** — кусок должен быть достаточно цельным (абзацы не рвутся) и достаточно коротким для точного поиска; перекрытие защищает ответы, «разрезанные» границей кусков.
- **Промпт-предохранитель от галлюцинаций** — модель обязана ссылаться на номера фрагментов и прямо говорить «в документах ответа нет».
- **Источники в каждом ответе** — доверие и проверяемость: сотрудник видит, из какого документа и раздела взят ответ.
- **eval.py** — качество RAG начинается с качества поиска: если нужный кусок не попал в топ-K, ответ будет плохим при любой LLM. Поэтому сначала меряем retrieval.
- **Ollama по умолчанию** — ИБ-сюжет: для многих предприятий отправка документов в облако недопустима; та же схема полностью локальна.

## Возможные развития (v2)

- Гибридный поиск (семантика + полнотекст) — для артикулов и номеров документов.
- Re-ranking найденных кусков второй моделью.
- Инкрементальная переиндексация (только изменённые файлы).
- PDF-документы и сканы (OCR).
