## Проект 1 (в работе): RAG-ассистент по производственной документации

**Цель:** показать на практике ключевое требование вакансии — RAG-ассистенты для работы с документами.

**Что делает:** отвечает на вопросы по техническим документам (регламенты, ГОСТы), указывая источник каждого ответа.

**Стек (план):**
- Python (OpenAI-совместимый API) или n8n (ноды AI: Embeddings, Vector Store)
- Эмбеддинги + векторное хранилище (Chroma / Qdrant / in-memory)
- Тестовый корпус: 2–3 открытых технических документа

## Проект 4 (идея): Автоматизация отчёта по НЗП (незавершённому производству)

**Цель:** показать end-to-end автоматизацию «как на реальном производстве»: отчёт по незавершенке собирается сам, по расписанию, с ИИ-комментарием к цифрам — без ручной выгрузки и сведения таблиц.

**Что делает:**
- по расписанию забирает данные по заказам и операциям из БД (SQL; на демо — генератор тестовых данных);
- считает НЗП по цехам/заказам: остатки, сроки, зависшие позиции, динамика к прошлому периоду;
- LLM готовит текстовую сводку к цифрам: узкие места, риски срыва сроков, что требует внимания руководителя;
- результат — Excel/PDF-отчёт + уведомление (email/Telegram).

**Стек (план):** n8n (расписание, ветки сценария) или Python; MS SQL / SQLite для демо-данных; OpenAI-совместимый API.

**Фишка для собеседования:** предметная область знакома досконально — легко отвечать на любые вопросы «а почему так устроено», в отличие от абстрактных демо.

**Статус:** 💡 идея

## Проект 5 (есть практика): Анализ конструкции на технологичность — локальная LLM

**Цель:** показать работу с локальными моделями: ИИ-проверка конструкторской документации на технологичность **без отправки данных в облако**.

**Что делает:**
- принимает на вход чертёж и 3D-модель детали (или только чертёж);
- LLM находит типовые проблемы технологичности (допуски, шероховатость, материал, термообработка и т.п.) и выдаёт замечания с рекомендациями;
- всё выполняется локально — чертежи и КД не покидают предприятие.

**Стек:** Ollama, модель **qwen3-vl:8b** — мультимодальная, читает чертёж напрямую; работает локально.

**Фишка для собеседования:** прямой ответ на главное возражение промышленных заказчиков — «у нас данные нельзя в облако». Уже есть действующая практика, не просто демо. Хорошо сочетается с Проектом 1 (RAG по ГОСТам) и вопросом об ИБ-ограничениях из плана собеседования.

**Статус:** 🛠 есть действующая практика — оформить в демо
